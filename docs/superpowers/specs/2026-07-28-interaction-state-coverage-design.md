# 交互状态覆盖设计

## 目标

将 HTML 页面中的未选择、选择后及依赖选择的后续操作作为独立可导入状态，同时避免为同一组列表项的每一个选择生成重复画面。

## 规则

- 显式配置的状态默认按语义去重；标记为 `capture: "always"` 的状态始终保留。
- 自动探索将可见的复选框、单选、选项、ARIA 选择控件，以及带 `cursor: pointer` 的卡片类元素作为候选动作。
- 同一选择组只探索第一个可用候选项。显式 `data-figma-state-group` 优先；否则根据控件类型、`name` 和最近的列表/表格/表单范围推断。
- 页面状态签名纳入选中、展开和禁用状态，保证未选择与已选择、以及操作可用性变化不会被误判为同一页面。
- 普通按钮、链接和现有排除规则保持不变。

## 验收

一个含两条同组渠道记录的页面应导出：默认列表、一个代表性的已选择列表，以及从该列表进入的注销和重新分配页面；不应为第二条渠道额外导出已选择状态。一个含两张同类 `cursor: pointer` 卡片的页面应导出列表和一个代表性详情页。
