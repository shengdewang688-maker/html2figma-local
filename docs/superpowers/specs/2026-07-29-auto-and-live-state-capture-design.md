# 自动探索与交互补录状态捕获设计

## 目标

将本地 HTML 原型转换为可编辑 Figma 画面，并尽可能自动覆盖所有可达界面；当自动探索未覆盖某个业务分支时，产品人员可直接操作原型，系统自动保存每一个有意义的界面状态并合并导入 Figma。

## 用户体验

1. 用户上传 HTML 项目并点击“自动识别”。
2. 工具在手机或桌面视口中探索交互，生成状态覆盖清单和 Figma bundle。
3. 用户查看自动结果；若有遗漏，点击“开始补录”。
4. 工具打开同一项目的本地预览；用户正常点击、输入、切换或提交。
5. 每次界面稳定后，工具自动保存状态，不要求用户标注页面或写选择器。
6. 用户点击“结束补录”；工具去重、合并自动和补录状态，随后导入 Figma。

## 状态模型

每个状态包含：可编辑 Scene JSON、截图基线、视口、状态来源（`auto` 或 `recorded`）、到达该状态的操作序列、DOM/视觉/交互签名和捕获时间。

操作包含：点击、输入提交或失焦、选择、键盘操作、路由变化和用户显式快照。纯滚动不单独生成状态；滚动后出现新内容、弹窗或布局变化时才生成状态。

## 自动探索

- 从每个已知状态重放操作路径，保证探索可重复。
- 候选动作来自原生交互语义、ARIA、可聚焦元素、页面路由、显式标记，以及能改变页面的非语义化可点击元素。
- 每次动作后等待网络、动画和 DOM 变更静止，再判断是否得到新状态。
- 使用状态签名去重；同一列表/卡片组保留代表路径，避免逐行生成视觉重复的画面。
- 对每个候选操作记录结果：新状态、重复状态、失败、超时或未观察到界面变化。

## 交互补录

- 本地预览在加载前注入捕获桥接脚本；它记录用户输入的操作和页面稳定事件。
- 用户可直接使用原型，不需要添加 `data-*` 属性或编辑源码。
- 页面发生可见变化后，桥接脚本将操作和状态快照提交给本地会话服务；服务为该状态生成 Scene JSON 与截图基线。
- 若补录状态与自动状态相同，则关联新的到达路径而不新增 Figma Frame。
- 用户可在补录面板删除误捕获状态、给状态重命名，或使用“保存当前状态”捕获无法由事件稳定检测到的画面。

## 覆盖报告

报告按状态图显示：已捕获状态、自动发现路径、补录路径、重复状态和未覆盖候选。

未覆盖候选必须说明原因：动作超时、触发外部链接、需要文件选择、需要认证/接口数据、页面未发生可见变化，或被安全策略跳过。这样产品人员知道需要补录哪个流程。

## Figma 输出

- 每个唯一状态生成一个顶层 Frame，名称包含状态名称和来源。
- Frame 写入共享插件数据：状态 ID、来源、操作路径和签名，便于追溯。
- 导入页按“自动识别”和“补录”两组排列；同一状态不重复导入。
- 现有文本、Frame、图片、SVG 和栅格回退规则继续使用。

## 安全与边界

自动探索默认不执行明确具有破坏性或外发效果的动作，例如删除、退出登录、支付、下载、上传、外部跳转和提交不可逆表单。它们保留在覆盖报告中，供用户在补录时自行触发。

插件不能凭空创建登录角色、后端返回数据或验证码状态；这些状态通过用户在已登录的本地预览中补录。补录后的状态仍会完整进入 Figma。

## 验收

- 自动模式能捕获标准按钮、标签、表单选择、非语义化可点击卡片和详情页。
- 两个同类卡片只生成一个代表详情状态，除非用户在补录中得到视觉或交互签名不同的页面。
- 用户点击进入一个自动未发现的详情、抽屉或弹窗后，无需配置即可自动记录并在结束补录后导入 Figma。
- 覆盖报告列出所有未成功探索的候选及其原因。
- 自动状态与补录状态合并后，重复状态只保留一个 Figma Frame。
