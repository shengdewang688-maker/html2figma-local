# 直接手动抓取模式设计

## 目标

在保留自动识别与后续补录的前提下，为产品人员提供完全不做自动探索的“直接手动抓取”入口。该模式确保用户可只保留自己指定的画面，并以首页作为完整流程的起点。

## 两种工作模式

### 自动识别 + 补录

用户上传项目后点击“开始自动识别”。系统探索入口 HTML 的可达状态，完成后可点击“开始补录”补充自动漏掉的分支。自动与补录状态按页面签名去重，合并导入 Figma。

### 直接手动抓取

用户上传项目并选择优先 HTML、视口和 Figma 页面名后，点击“直接手动抓取”。系统不执行候选交互探索，立即打开补录窗口，并自动保存当前首页一次。用户在窗口中正常操作；仅用户点击右下角“抓取当前页面”或工具页同名按钮时，才保存后续页面。点击“结束补录”后生成 bundle。

## 数据与导入

- 直接手动模式的首页状态来源为 `explicit`，操作路径为 `navigate`。
- 用户手动保存的状态来源为 `recorded`。
- 两种模式都使用同一个状态仓库、截图、去重规则和 `/session/latest`。
- Figma 导入后仍按“初始 / 自动 / 补录”来源命名 Frame；直接手动模式不会产生“自动”状态。

## 界面与状态

- 上传文件后，主操作区同时展示“开始自动识别”和“直接手动抓取”。
- 直接手动抓取在没有 HTML、转换任务运行中或已有补录会话运行中时禁用。
- 进入手动模式后，工具页状态显示“已保存首页，等待抓取页面”；补录窗口显示“抓取当前页面”按钮。
- 结束补录时摘要显示初始、自动、补录、去重数量，清楚提示是否真正保存了后续页面。

## 验收

1. 选择直接手动抓取后，不执行自动探索，报告 `coverage.auto` 为 0。
2. 未点击任何抓取按钮就结束时，bundle 仅有首页状态。
3. 用户抓取一个详情页后，bundle 有首页和该详情页，详情来源为 `recorded`。
4. 自动识别 + 补录的现有流程不变。
5. 两个模式都可从 Figma 插件读取 `http://localhost:4777/session/latest` 并导入。
